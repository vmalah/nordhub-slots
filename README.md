# NordHub Slots — демо-проект AI-augmented QA

Учебный pet-проект: портал перевозчика вымышленного склада **NordHub**.
Перевозчик смотрит расписание разгрузки, бронирует часовой слот и управляет своими бронями.

Проект создан, чтобы показать, как QA-инженер встраивает AI в ежедневную работу:
анализ требований и кода, поиск рисков, генерацию тест-кейсов и автотестов,
ускорение регрессии и синхронизацию с разработкой.

> Все данные вымышленные. В код фичи бронирования **намеренно заложены дефекты** —
> их находит QA-процесс, показанный в демо.

## Связанные артефакты

| Что | Где |
| --- | --- |
| Требования (user story + AC) | Jira, задача `SCRUM-5` в демо-проекте |
| Макет | Figma, файл «QA Demo — NordHub: бронирование слота» |
| Автотесты | `tests/` (Playwright) |
| CI | `.github/workflows/qa.yml` — тесты на каждый PR |

## Запуск

```bash
npm run setup       # npm install + браузер (или предустановленный Playwright)
npm start            # приложение: http://localhost:4173
npm test             # все автотесты
npm run test:smoke   # только смоук
```

Текущее время в приложении можно зафиксировать параметром `?now=`:
`http://localhost:4173/?now=2026-10-15T10:00:00#/schedule`.
Это хук тестируемости: окна бронирования и отмены зависят от времени,
и без него проверки были бы нестабильными.

## Карта модулей → теги тестов

Используется для выбора регрессии по изменениям в PR (вручную или с помощью AI).

| Файлы | Модуль | Тег тестов |
| --- | --- | --- |
| `public/js/slots.js`, `public/js/data.js` | Расписание слотов | `@schedule` |
| `public/js/booking.js`, `public/js/api.js` | Форма бронирования | `@booking` |
| `public/js/storage.js` | Мои брони | `@bookings` |
| `public/js/app.js`, `public/js/clock.js`, `public/styles.css` | Общее | все тесты |

Запуск по тегам: `npx playwright test --grep "@schedule|@booking"`.
В GitHub Actions — кнопка **Run workflow** с полем `grep`.
